# vaporizer-price-study

Secondary-market price analysis of anaesthetic vaporizers (desflurane, sevoflurane,
isoflurane) around the EU desflurane prohibition, using three years of eBay Terapeak
completed-sale data.

- **Published article:** https://doi.org/10.1016/j.jatmed.2026.08.002
- **Study design:** retrospective cross-sectional analysis of completed sales; natural
  experiment with sevoflurane and isoflurane as unregulated comparators.

## Data provenance

- Sale prices come from **eBay Terapeak** 3-year completed-listing exports
  (`data/terapeak_*.csv`), collected March 2026. Data cover 2023-03-28 to 2026-03-24.
- Asking prices (`data/ebay_asking_prices.csv`) are a one-time scrape of active
  listings (27 March 2026) used only for supplementary Table S1.
- Other reseller files (`bimedis_data.csv`, `bma_data.csv`, `dotmed_data.csv`,
  `worthpoint_data.csv`, `supplementary_reseller_data.csv`, `terapeak_unified.csv`)
  were collected for sensitivity exploration but are **not** used by the published
  analysis, which restricts to a single marketplace to avoid cross-listing duplicates.
- eBay/Terapeak data are redistributed here for reproducibility; marketplace terms of
  use may apply to downstream use.

## Reproduce the analysis

Requires Python ≥ 3.9 (developed on 3.12; regression-tested on 3.10).

```bash
pip install -r requirements.txt
cd vaporizer-price-study        # the project directory inside the repo
python analyze.py               # -> data/combined_cleaned.csv, statistics_summary.csv,
                                #    regulatory_timeline.csv, figures/fig1-6.{png,pdf}
python create_jca_tables.py     # -> papers/jca_table{1,2,s1}.docx
python write_jca_english.py     # -> papers/jca_manuscript_english.docx   (optional)
python analyze_asking_prices.py # -> data/asking_price_analysis.json      (optional)
python -m pytest tests/ -v      # regression tests (see below)
```

All scripts resolve their inputs/outputs relative to their own location
(`Path(__file__).resolve().parent`), so they also run from any other working
directory, e.g. `python /path/to/repo/vaporizer-price-study/analyze.py`.

## Statistical methods — exact specifications

### Pre-/post-ban comparison (`analyze.py`, `create_jca_tables.py`)

- Cutpoint: **2026-01-01** (desflurane prohibition, Regulation (EU) 2024/573).
  Sales on/after this date are "post".
- Mann–Whitney U (two-sided), Welch's t-test (`scipy.stats.ttest_ind`,
  `equal_var=False`), Cohen's d = (post − pre)/pooled SD where
  pooled SD = sqrt((var_pre + var_post)/2). The 95% CI for d uses the
  Hedges–Olkin SE: `sqrt((n1+n2)/(n1*n2) + d²/(2(n1+n2)))` and ±1.96·SE.
- Between-agent effect-size comparison: z-test on Δd with
  `SE = sqrt(SE1² + SE2²)`.

### Regulatory phase coding (1–5)

Defined in `create_jca_tables.py::classify_period` (identical logic in
`analyze.py::classify_period`, which returns named labels `1_Pre-proposal` …
`5_Post-ban`). Boundary dates are **left-exclusive**: a sale dated exactly on a
boundary belongs to the *later* phase.

| Phase | Label | Date interval (start inclusive, end exclusive) |
|---|---|---|
| 1 | Pre-proposal | sale date < 2022-04-05 |
| 2 | Post-proposal | 2022-04-05 ≤ date < 2023-10-05 |
| 3 | Post-agreement | 2023-10-05 ≤ date < 2024-02-07 |
| 4 | Post-adoption | 2024-02-07 ≤ date < 2026-01-01 |
| 5 | Post-ban | date ≥ 2026-01-01 |

Anchors: EC proposal 2022-04-05; trilogue provisional agreement 2023-10-05;
formal adoption (Regulation (EU) 2024/573) 2024-02-07; ban effective 2026-01-01.
Additional timeline-only events used for figures (not for phase coding):
EP plenary vote 2023-03-30; regulation in force 2024-03-11.

Note: the observed data begin 2023-03-28, so phase 1 is empty in practice and
`period_num` takes values 2–5.

### Trend tests (`create_jca_tables.py::compute_trend`)

- **Spearman's rank correlation** (`scipy.stats.spearmanr`, two-sided) is
  calculated between **individual sale dates** (encoded as `date.toordinal()`)
  and vaporizer sale prices. Missing prices/dates are dropped at load
  (`dropna(subset=['date_sold','price_usd'])`).
- **Kendall's tau** (`scipy.stats.kendalltau`, default settings — i.e. **tau-b**,
  which adjusts for ties; verified against `scipy 1.15` signature
  `variant='b'`) is calculated between the **ordinal regulatory phase (coded
  1–5)** and sale prices, *not* between continuous sale dates and prices.
- Consequently, the Spearman and Kendall analyses address related but distinct
  temporal associations and are not interchangeable estimates of the same
  relationship.
- **Quarterly-median trend:** per agent, sales are grouped by calendar quarter;
  quarters with `count < 3` are dropped; Spearman's rho is then computed between
  the **quarter sequence index** (`0..len(qm)-1`) and the quarterly median price.
  This test therefore uses a different independent variable (quarter rank) than
  the listing-level tests.

### Sensitivity analyses

The published article reports four sensitivity analyses, implemented by
`vaporizer-price-study/revision_sensitivity_analysis.py` (recovered from the
revision branch `devin/jatm-minor-revision-r1`, where they were produced for the
article's R1 revision; an earlier revision of this README wrongly stated they
were unreported — corrected in the VOR audit, see
`audit/PREVIOUS_AUDIT_RECONCILIATION.md`):

- **Bootstrap pre/post CIs**: 10,000 resamples within pre and post groups;
  percentile 95% CIs for mean and median differences; seed
  `np.random.default_rng(20260729)`.
- **Post-hoc power simulation**: lognormal MLE on log prices per group; 10,000
  simulated pre/post pairs at observed n; power = fraction with P < 0.05.
- **Difference-in-differences**: OLS on `log_price` with agent-specific post and
  trend interactions (sevoflurane reference), HC3 robust SE.
- **CITS**: OLS on monthly median `log` price with level/slope intervention
  terms per agent, HAC (maxlags=3) SE.

Outputs: `data/revision_sensitivity.json` and
`data/revision_sensitivity_its.csv`. Re-running the script regenerates the JSON
identically (seeded). These are sensitivity analyses; their causal assumptions
are only partly met (see article).

## Tests

`python -m pytest tests/ -v` recomputes the published counts, pre/post
statistics, and all three trend tests from the raw CSVs (not from cached
outputs), checks phase-boundary logic implicitly via the reported statistics,
verifies no machine-specific absolute paths remain in scripts, and executes
`analyze.py` and `create_jca_tables.py` from a directory outside the repo.
Numerical tolerances: counts exact; means/SDs ±0.5 USD; correlations ±0.005;
p-values within ±5% relative or ±0.001 absolute.

## Reproducibility limitations

- `data/combined_cleaned.csv`, `statistics_summary.csv`, and
  `regulatory_timeline.csv` are generated artifacts that are also checked in;
  `analyze.py` overwrites them. Regeneration is byte-identical for
  `combined_cleaned.csv`; `statistics_summary.csv` can differ in last-ulp float
  digits across scipy versions.
- Figures are regenerated deterministically but image bytes depend on
  matplotlib/seaborn versions (fonts, anti-aliasing); values plotted are the same.
- `analyze_old.py` is quarantined under `legacy/` (VOR audit, 2026-10-26): it
  uses a different cleaning pipeline (includes Worthpoint data) and previously
  wrote to the same output filenames as `analyze.py`, clobbering published-path
  outputs when run. Under `legacy/` its derived paths no longer collide. It is
  retained for provenance only.
- `write_papers.py`, `write_anaesthesia_*.py`, `gen_*.py`,
  `patch_papers.py`, and the scraper/compile scripts are retained for
  provenance. They run from any directory but are **not** the published
  analysis path.
- Scrapers (`scrape_asking_*.py`, `worthpoint_collector.py`) require live
  network access and marketplace credentials/selectors that are time-sensitive;
  they are included for provenance only.

## Audit

An independent computational-integrity and reproduction audit (baseline
inventory, portability fixes, full numerical reproduction, data–text–figure
consistency, adversarial review, QC report) is documented under
`vaporizer-price-study/audit/`. A follow-on **Version-of-Record audit**
(2026-10-26) retrieved the published article (PMC13573186), recovered the
original sensitivity-analysis code, and reproduced every published number —
see `audit/VOR_FINAL_QC_REPORT.md`.

Reproduction tiers used in the audit:

- **ORIGINAL-CODE REPRODUCED** — original script executed, published value
  produced exactly (all primary statistics and all four sensitivity analyses).
- **NUMERICALLY CONSISTENT** — value matches; exact generating path or
  environment not byte-identical (Table S1; package-version drift).
- **NOT VERIFIED** — could not be checked (ScienceDirect PDF vs PMC text;
  buyer geography — data do not exist).

No analysis required independent reimplementation: all VOR numbers were
reproduced by the original code. Thanks to external reproducibility feedback for
motivating the portability and specification fixes in this revision.
